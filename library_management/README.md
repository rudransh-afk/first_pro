# Library Management System

A simple full-stack library management system.

- **Backend:** FastAPI + SQLAlchemy + SQLite
- **Frontend:** Plain HTML/CSS/JavaScript (no build step, no framework)
- **Features:** manage books, manage members, checkout/return books (with live availability tracking)

The FastAPI backend also serves the frontend directly, so the whole app runs as a single process on one port.

## Project structure

```
library_management/
├── backend/
│   ├── main.py          # FastAPI app + routes + serves the frontend
│   ├── models.py        # SQLAlchemy ORM models (Book, Member, Loan)
│   ├── schemas.py        # Pydantic request/response schemas
│   ├── crud.py            # Database operations & business logic
│   ├── database.py        # DB engine/session setup
│   └── requirements.txt
├── frontend/
│   ├── index.html
│   ├── style.css
│   └── app.js
├── Dockerfile
├── docker-compose.yml
└── README.md
```

## Run it locally (no Docker)

Requires Python 3.10+.

```bash
cd library_management/backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn main:app --reload
```

Then open **http://127.0.0.1:8001** in your browser — that's the app itself.
Interactive API docs (auto-generated by FastAPI) are at **http://127.0.0.1:8001/docs**.

A `library.db` SQLite file is created automatically on first run in the `backend/` folder.

## Run it with Docker (recommended)

```bash
cd library_management
docker compose up --build
```

Open **http://localhost:8001**. The SQLite database persists in a Docker volume (`library-data`) between restarts.

To stop: `docker compose down` (data is preserved). To wipe data too: `docker compose down -v`.

## API overview

| Method | Endpoint                     | Description                  |
|--------|-------------------------------|-------------------------------|
| GET    | `/api/books`                  | List/search books            |
| POST   | `/api/books`                  | Add a book                   |
| PUT    | `/api/books/{id}`             | Update a book                |
| DELETE | `/api/books/{id}`             | Delete a book                |
| GET    | `/api/members`                | List/search members          |
| POST   | `/api/members`                | Add a member                 |
| PUT    | `/api/members/{id}`           | Update a member               |
| DELETE | `/api/members/{id}`           | Delete a member               |
| GET    | `/api/loans?active_only=true` | List loans                    |
| POST   | `/api/loans/checkout`         | Check out a book to a member  |
| POST   | `/api/loans/{id}/return`      | Return a book                 |

Full interactive documentation with request/response schemas is available at `/docs` while the server is running.

## Deploying for real

The app is a single container exposing port 8000, so it works with any host that runs Docker containers:

### Option A: Render / Railway / Fly.io (easiest, free tiers available)
1. Push this project to a GitHub repository.
2. Create a new "Web Service" (Render) or project (Railway/Fly) and point it at the repo.
3. It will detect the `Dockerfile` automatically and build/deploy it.
4. Set the exposed port to `8000` if asked.

### Option B: Any VPS (e.g. DigitalOcean, EC2, Hetzner)
```bash
git clone <your-repo-url>
cd library_management
docker compose up -d --build
```
Then put a reverse proxy (Nginx or Caddy) in front of port 8000 for HTTPS and a domain name.

### Notes for production use
- SQLite is fine for a small/personal deployment. For multiple concurrent users, swap `SQLALCHEMY_DATABASE_URL` in `backend/database.py` for a PostgreSQL connection string and add `psycopg2-binary` to `requirements.txt`.
- There is currently no authentication — anyone with the URL can use the app. Add login/roles before exposing it publicly to real users.
- Back up the `library.db` file (or the Docker volume) periodically.
